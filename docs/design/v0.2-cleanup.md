# v0.2 API Cleanup & Composition Verification

依据：用户《收尾迭代计划与 Hooks API 定案》。基线：已合并 PR #7，main 的 2d0e47d。此前提案中的注册便利入口决定由本次定案替代。

## 改动与取舍

Core 只删除 Interactor:use 及专属运行点校验表；构造时仅校验实际调用的 Hooks before/after 方法。注册统一使用 Hooks:on(point,fn)，由宿主启动期显式组装，Interactor 不再管理注册。现有 Hooks 数组分发、快照和异常隔离保持不变，只增加启动期配置的注释。

同点 FIFO 和跨点阶段顺序是两件事。现有 pairs 并未破坏固定阶段；删除便利入口是精简公共 API，而不是新增排序机制。固定阶段仍为通用 BEFORE → 专属 BEFORE → 操作 → 专属 AFTER → 通用 AFTER。不支持执行操作期间更改注册，不增加优先级、排序器、批量注册、freeze/lock 或插件生命周期。

Domain、Repository、CodeGenerator、HookPoint、根导出和四个生产 Adapter 均保持原契约。不自动修改 Repository 的 Lifecycle 配置；宿主向 Repository 与 Interactor 注入同一套函数。版本仍为正在收尾的 v0.2.0；迁移说明明确记录删除已进入主分支的临时方法这一破坏性变化。

## 组合验证

| 场景 | 使用方式 | 验证边界 |
| --- | --- | --- |
| 自增 ID＋Base62 | Composed(Sequential→Base62) 注入 CodeGenerator | 61→z、62→10，生成后可解析 |
| URL→Code | 宿主 CodeGenerator 从输入 URL 提取选定路径 slug | 确定性、错误、原样 ctx、碰撞由 Repository 返回 CONFLICT，不重试 |
| 三级存储 | 测试内组合两个读前层及一个权威层，均使用真实 InMemory | 冷读、二层/一层命中、独立快照、成功写入失效、删除保留、缺失/故障区分 |

三级组合只存在于 spec/composition_spec.lua，所有写入均经同一个权威层；未验证外部写入、跨进程失效、真实数据库并发、负缓存或外部产品。URL slug 只是宿主策略示例，不新增内置 URL 哈希算法。不开新 examples 框架或生产适配器。
