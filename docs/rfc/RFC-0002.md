| Field | Value |
| --- | --- |
| Status | Initial v0.2 merged in PR #7; Hooks cleanup follows the final on-only contract |
| Version | 0.2.0 |

MUST, MUST NOT and SHOULD below describe conformance requirements. [API reference](../api.md) gives exact signatures; [migration notes](../migration-v0.2.md) list breaking changes. The [v0.1 RFC](RFC-0001.md) remains historical.

## 1. Position and iron rules

**SLDS = Identity + Lifecycle + Resolution Semantics.** Core remains a small pure Lua library; the host explicitly assembles dependencies. It MUST NOT introduce an HTTP server, database/cache client, JSON library, target request, scheduler, authorization system or durable event framework.

| Rule | Requirement |
| --- | --- |
| RULE-001 | Core MUST NOT depend on HTTP. |
| RULE-002 | Core MUST NOT depend on a specific database. |
| RULE-003 | Core MUST NOT fetch Target URLs. |
| RULE-004 | Identity namespace/code MUST remain immutable after creation. |
| RULE-005 | Repository MUST enforce identity uniqueness atomically. |
| RULE-006 | Deleted identities MUST remain reserved by default. |
| RULE-007 | Resolution MUST NOT require an external event/analytics system to succeed. |
| RULE-008 | Analytics delivery MUST remain outside the resolution critical path. |
| RULE-009 | Authorization MUST be implemented by the host. |
| RULE-010 | Compatibility claims MUST pass applicable conformance scenarios and declare evidence scope. |

Hooks are synchronous observation points. Exception isolation satisfies no latency or telemetry delivery guarantee; the host owns any bounded/asynchronous delivery path needed by RULE-008.

## 2. API and dependency boundary

Core exposes only four operations through Interactor: create, resolve, update and delete. Root exports VERSION, new, Interactor, Identity, ShortLink, Lifecycle, Resolution, Errors, Hooks and HookPoint. It MUST NOT expose redundant flat status/error aliases or the former Service.

Core's dependency ports are Repository and optional CodeGenerator. Generator/Encoder remain adapter-internal components; numeric ranges, alphabets and ID representations MUST NOT constrain the generic Core port. No port inheritance or dependency container is required. ctx is an opaque table passed unchanged; it is not a dependency locator or authorization mechanism.

Constructors MUST validate injected method/function shapes. Missing Lifecycle predicates MUST be filled using defaults without modifying the host's table. The host MUST configure consistent Lifecycle functions at Interactor and authoritative Repository boundaries.

## 3. Identity, entity and rules

Identity is the `{namespace,code}` tuple of non-empty strings. It is logically immutable, represented by an ordinary Lua table with shared class metatable. Callers MUST NOT rewrite identity fields. Storage MUST preserve distinct valid tuples, including NUL-containing strings; a delimiter display string is not sufficient as a storage key.

ShortLink stores identity, target, status, optional expires_at and opaque metadata. Target MUST be a non-empty string and MUST reject javascript:, data: and file: schemes after whitespace/case normalization. Core does not fetch or fully parse the target; host policy may be stricter. Expiration MUST be nil or a finite number. Metadata MUST be nil or a table.

Only ACTIVE, DISABLED and DELETED may be persisted. Lifecycle exposes is_valid, can_transition and is_resolvable. Defaults permit ACTIVE↔DISABLED and ACTIVE/DISABLED→DELETED. Same-status patches do not invoke the transition predicate. Partial overrides may restrict states/transitions or customize resolvability, but MUST NOT admit unknown statuses, revive DELETED or resolve DELETED. Invalid business values/transitions return INVALID.

ShortLink.new(data,rules?) and with_patch(patch,rules?) perform domain validation. The allowed patch fields are target/status/expires_at. Namespace/code patches are programming errors; all other keys, including metadata, return INVALID. Nil expiration means unchanged. v0.2 defines no expiration-clearing sentinel; false is INVALID.

Metadata table graphs MUST be independently captured at construction, patch, export, storage and observer boundaries. Preserve graph cycles/shared children/table keys; omit metadata metatables without invoking them. Non-table leaves retain their values; host resource internal state is outside the snapshot guarantee. Adapters may declare a narrower serializable value set and MUST validate it.

## 4. Resolution

Resolution MUST be a pure domain decision and MUST NOT write Repository. It evaluates:

1. No record: found=false, resolvable=false, status=NOT_FOUND.
2. DELETED: found=true, resolvable=false, status=DELETED.
3. Lifecycle denies resolution: found=true, resolvable=false, actual persistent status.
4. expires_at <= now: found=true, resolvable=false, status=EXPIRED.
5. Otherwise: found=true, resolvable=true, actual persistent status and target.

EXPIRED belongs to Resolution.EXPIRED and MUST NOT be persisted. The result includes namespace/code, found, resolvable, status, optional target and expires_at. Target MUST be absent when not resolvable. If custom rules allow DISABLED, a successful result MUST retain DISABLED. Hosts SHOULD decide behavior from resolvable rather than status comparisons.

Repository NOT_FOUND becomes a normal absence result. Infrastructure errors MUST remain distinct nil,err. The injected clock MUST return a finite number.

## 5. Errors and programming contracts

The stable error set is exactly NOT_FOUND, CONFLICT and INVALID. Expected failures return nil,err; successful values return value,nil. Delete success is true. Infrastructure errors MUST pass unchanged, without prefixes or broad exception conversion.

Missing argument containers, invalid injected methods, identity mutation attempts, malformed port responses and thrown unexpected failures are programming errors. Nil,nil from a dependency and simultaneous result/error are programming errors. A programming exception MAY propagate without AFTER; normal success and failure returns MUST trigger AFTER.

## 6. Code generation

CodeGenerator.generate(ctx,input) MUST return final non-empty string Code or nil,err. Only input.code==nil invokes it. Explicit invalid/empty Code returns INVALID; missing Code without a generator returns INVALID. Create fixes status to ACTIVE and rejects explicit status. The generator MUST receive independent input and unchanged ctx. Core MUST NOT coerce IDs, retry conflicts or interpret deterministic generation as idempotency.

The reference Composed adapter calls inner generator.generate(ctx), then each encoder.encode(previous) in a captured dense array. Empty arrays are allowed. Intermediate representations remain opaque; only nil signals failure. It MUST stop at first failure, preserve its error, reject malformed response pairs, and validate only the final non-empty string. This does not introduce a Core pipeline framework.

Sequential/Base62 retain exact integer range [0,2^53-1]; Sequential uniqueness is instance-local and exhaustion persists after returning the maximum once. These limits belong to reference adapter contracts. Full uint64/string IDs need separately compatible components.

## 7. Authoritative Repository

Repository implements create/get/update/delete. Success entities MUST be independent of storage. Create MUST reserve identity atomically, including existing DELETED records. Missing get/update/delete returns NOT_FOUND. Get retrieves an entity without applying Resolution.

Interactor.update/delete MUST NOT pre-read. Repository.update MUST atomically locate the latest record, reject DELETED, validate the complete candidate using the raw sparse patch, evaluate optional can_update, then commit. Invalid fields MUST be rejected before policy evaluation. Unspecified fields MUST remain intact; failure MUST leave storage unchanged.

can_update(current,patch) is an adapter-injected pure synchronous non-yielding boolean predicate, not a Core port. False returns INVALID. Exception or non-boolean return is a programming error with rollback. Its observations MUST NOT alias actual committed data. It MUST NOT run for delete.

Delete MUST validate the complete candidate and current→DELETED transition, including custom is_valid(DELETED). Repeat deletion returns INVALID and MUST NOT erase the identity reservation.

Different-field sparse updates preserve each other; same-field updates follow commit order. This does not promise application stale-read detection. External adapters MAY implement host-specific ctx CAS conditions and return CONFLICT; v0.2 adds no generic version fields. Cache decorators MAY implement the same port, with declared consistency and separate tests. Neither external CAS nor caching is bundled or proven by reference tests.

## 8. Hooks

Hooks stores ordered callback arrays by HookPoint: BEFORE/AFTER, operation-specific before/after points and ON_ERROR. Order MUST be general BEFORE → specific BEFORE → operation → specific AFTER → general AFTER, with registration order within a point.

BEFORE follows programming argument checks and snapshot capture, preceding generation/business validation. Every normal return MUST reach the corresponding specific/general AFTER exactly once. Callbacks use `(ctx,point,payload...)`; AFTER includes value,err and AFTER_DELETE includes ok,err. ON_ERROR uses `(ctx,failed_point,hook_err)` and MUST NOT recurse on its own failure.

Each callback MUST receive independent domain payload snapshots preserving root domain methods and nil argument positions. ctx MUST retain its original reference and SHOULD be read-only. Callback returns are ignored; each callback exception is isolated with pcall. No timeout, sandbox, asynchronous scheduling or durable delivery is promised. Empty points SHOULD avoid snapshot allocation.

hooks:on(point,fn) MUST be the only registration entry. Interactor MUST only dispatch observers and MUST NOT expose registration methods. Hosts MUST finish registration at application startup before invoking operations. Mutation of registrations during operations is unsupported; implementations MUST NOT add priorities, global sorting or lifecycle/freeze APIs for this iteration.

## 9. Verification and delivery

All production Lua files under src/ and adapters/ MUST individually reach at least 95% line coverage, including unloaded files, port stubs and internal helpers. Fresh LuaCov measurements MUST run separately on Lua 5.1, Lua 5.3 and LuaJIT. Codecov project/patch targets remain at least 95%, with zero tolerance. Aggregate or merged coverage cannot replace per-file gates.

Reference conformance MUST use actual bundled adapters with fresh fixture factories. Fault injection MAY replace specific methods. Deterministic interleavings MUST NOT be advertised as external concurrency proof, ctx propagation as tenant isolation, or uncached visibility as cache invalidation. Exact interpreter/test/file results and remote status belong in [validation records](../validation.md).

The latest supplemental design defers its earlier expiration-clearing goal; this difference is explicit in migration notes. Local ignored OpenSpec proposals/specs are not part of the Git delivery unless repository policy changes.
